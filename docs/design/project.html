Aztecscan

CI/CD, production Kubernetes and full-stack work on the block explorer for Aztec, a privacy-focused L2 — 678 commits over 21 months.

The problem

A privacy L2 moves fast and hides most of its interesting state. The explorer has to keep up with a protocol that was not version-stable: over 21 months we tracked more than ten Aztec releases, and three live networks deliberately ran different protocol versions at the same time. The delivery pipeline had to carry all of that without freezing the product.

My role and what I owned

I was the second engineer on Aztecscan and stayed for 21 months — 678 of the repo's 1,812 commits (about 37%), and 128 merged pull requests. I was not the project lead. Filip started the repo and is the largest contributor; the database schema was primarily his.

What I owned: the per-service CI/CD workflows, the production Kubernetes manifests for the explorer API, UI, websocket publisher, listeners and gateways, the migration off Skaffold, and the AI-agent tooling — a 296-line devops.md agent persona covering the repo's Kafka conventions and release process.

The hard part

Migrating from Skaffold to GitHub Actions plus Kustomize, one service at a time, with no freeze. explorer-ui-v2 was the live pilot; the pattern was then copied to seven more services while the old pipeline kept deploying the rest.

The decision that cost the most was trusting Kustomize to rename consistently. nameSuffix rewrites metadata.name, but it does not rewrite HTTPRoute.spec.rules[].backendRefs[].name. Traffic routed silently to a service that no longer existed. The "obvious" alternative — hand-editing every reference per overlay — was rejected because it drifts the moment someone forgets, but the accepted cost is a hardcoded suffixed name that must always match. 

# services/explorer-ui/k8s/overlays/mainnet/kustomization.yaml
nameSuffix: -mainnet
patches:
  - target: { kind: HTTPRoute, name: explorer-ui }
    patch: |-
      - op: replace
        path: /spec/rules/0/backendRefs/0/name
        value: explorer-ui-mainnet   # must match nameSuffix exactly

$ kubectl kustomize services/explorer-ui/k8s/overlays/mainnet \
    | yq '.spec.rules[0].backendRefs[0].name'
explorer-ui-mainnet

Outcome

Every service now owns its Dockerfile and a path-filtered workflow; the repo carries 9 services and 11 shared packages across 5 environments. The CI/CD migration landed as PR #625: +4,925 / −80 lines over 79 files. The three live networks kept deploying throughout.

What I'd do differently

The migration document, 459 lines long, recorded both footguns after they bit. The overlay invariant — every backendRefs name is the base name plus the overlay's suffix — should have been written down before the first service moved, and checked by one command rather than by whoever remembered.
